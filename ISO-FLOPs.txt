The full IsoFLOPs cycle

Step 1 — Fix compute

Choose a budget, for example C=600.

Step 2 — Choose model sizes

Try small, medium, and large models.

Step 3 — Calculate token budgets

Use the fixed-compute constraint to determine how many tokens each model can process.

Step 4 — Train the models

Train each model using its assigned token budget.

Step 5 — Measure loss

Compare the final validation loss of each model.

Step 6 — Find the best point

The lowest-loss model is the compute-optimal choice for that budget.

Step 7 — Increase compute and repeat

Try a larger budget, such as C=6,000, and repeat the experiment.

That repeated process is what people mean when they talk about the IsoFLOPs cycle.

What do we conclude?

Notice what we did not conclude:

We did not say the largest model is always best.

We did not say the smallest model is always best.

We did not say more tokens are always best.

We found the best balance for this fixed compute budget.

The key equation

A simplified estimate for Transformer training compute is:

C≈6ND

Where:

Symbol

	

Meaning




C

	

Total training compute




N

	

Number of model parameters




D

	

Number of training tokens




6

	

Approximate constant for a standard dense Transformer training estimate

Important: This is an approximation used for scaling-law reasoning, not an exact compute count for every architecture.

Now look at what happens if we keep C fixed.

Suppose:

C=600

Then:

6ND=600

So:

ND=100

That means:

If the model gets bigger, the number of training tokens must decrease to keep compute the same.
