3.Flash Attention
NOrmal attentions has a major memory-bandwidth bottleneck , especially for long sequences 
flash attentions improves this by reducing expensive memory transfers between GPU high bandwith memory and faster on-chip memory while performing the attention calculation.

Normal Attention
GPU memory ↔ fast memory
many transfers ❌

Flash Attention
load efficiently → compute
fewer transfers ✅

4.vLLM 
--> LLM serving framework designed around efficient GPU utilization and paged attention.
during genration model stores previous K V tensors in KV cache 
with many users 
request 1 --> KV CACHE 
request 2 --> KV cache 
request 3 --> KV cache 

Paged Attention
 vLLM divides KV-cache memory into smaller pages/blocks instead of requiring one large continuous memory region
 KV Cache

Traditional:
[████████████████████]  one large block

vLLM:
[██][██][██][██][██]
 pages

 
 A page table keeps track of where each sequence's pages are stored. Pages can also be shared in some situations
 
vLLM → PagedAttention → efficient KV-cache memory management.

5. llama.cpp
It is a highly optimized C/C++ implementation designed especially for running LLMs efficiently on consumer hardware/CPUs, with optional GPU acceleration.


Quantization

Instead of storing weights as:

FP32 / FP16
FP ---> floating point 
you can use lower-precision formats such as:

INT8
INT4
etc.

This greatly reduces memory requirements and can make local inference practical.

Large FP16 model
      ↓ quantization
Smaller 4-bit model
      ↓
Less RAM/VRAM needed

It commonly uses the GGUF model format for this style of inference.

7. What is batching here?

Suppose 3 users send requests:

User A → "Explain CNN"
User B → "Explain RNN"
User C → "Explain Transformers"

Instead of inefficiently processing everything separately, serving systems can organize requests so the GPU is continuously doing useful work.

This is why batching is so important in production LLM serving. TGI specifically uses continuous batching.
