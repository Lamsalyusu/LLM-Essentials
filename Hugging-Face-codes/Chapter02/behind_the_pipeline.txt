A pipeline has three major steps

Input text
    ↓
1. Preprocessing
    ↓
2. Model inference
    ↓
3. Postprocessing
    ↓
Final result

============================================================

For example:

from transformers import pipeline

classifier = pipeline("sentiment-analysis")

classifier("I love this!")

==============================================================

Underneath, HF is essentially doing:

"I love this!"
      ↓
   Tokenizer
      ↓
Token IDs + Attention Mask
      ↓
Transformer Model
      ↓
Model Head
      ↓
Logits
      ↓
Softmax
      ↓
POSITIVE: 0.99

================================================================

Transformers cannot directly understand raw text.

The tokenizer:

Text
 ↓
Tokens
 ↓
Token IDs
 ↓
Model inputs

==================================================================
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(checkpoint)

Tokenizer converts human language into numerical inputs that the Transformer can process.

==================================================================

input_ids

The tokenizer returns something like:

{
    "input_ids": [...],
    "attention_mask": [...]
}

input_ids

These are the integer IDs representing the tokens.

"I love cricket"
      ↓
[101, 1045, 2293, ...]

The model uses these IDs to obtain the corresponding embeddings.

=============================================================================

attention_mask

You will see this everywhere in Hugging Face.

Example:

input_ids:
[101, 1045, 2293, 102, 0, 0, 0]

attention_mask:
[ 1,    1,    1,   1, 0, 0, 0]

1 means:

This is a real token.

0 means:

This is padding; ignore it.

You don't need to go deeply into padding/truncation yet; HF covers those immediately afterward.

return_tensors="pt" ⭐

This is particularly relevant because you're learning PyTorch.

inputs = tokenizer(
    text,
    return_tensors="pt"
)

"pt" means:

Return PyTorch tensors

Other frameworks can have their own tensor formats.

6. Model

Now we feed those inputs into a pretrained Transformer.

HF provides:

from transformers import AutoModel

model = AutoModel.from_pretrained(checkpoint)

The important concept:

AutoModel
   ↓
Base Transformer
   ↓
Hidden states

The base Transformer doesn't necessarily directly give you "POSITIVE" or "NEGATIVE".

It produces hidden states — high-dimensional representations containing contextual information.


Hidden States ⭐⭐⭐⭐⭐

This is VERY important.

Suppose:

"I love cricket"

After passing through the Transformer, you might get:

[batch, sequence_length, hidden_size]

For the HF example:

[2, 16, 768]

Meaning:

2    → number of sentences
16   → tokens per sentence
768  → representation size of each token

So remember:

Hidden states are the rich contextual representations produced by the Transformer.


Model Head ⭐⭐⭐⭐⭐

This is another concept you should not forget.

The Transformer is often just the base.

A task-specific head is placed on top.

                 Transformer
                      ↓
                Hidden States
                      ↓
                 Task Head
                      ↓
                   Output

Different tasks → different heads.

For example:

AutoModelForSequenceClassification

has a classification head.

AutoModelForCausalLM

has a language-modeling head for predicting tokens.

HF lists several architectures including *ForCausalLM, *ForMaskedLM, *ForQuestionAnswering, *ForSequenceClassification, and *ForTokenClassification



9. AutoModel vs AutoModelFor... ⭐⭐⭐⭐⭐

This is something you should definitely put in your notes.

AutoModel
model = AutoModel.from_pretrained(...)

Gives you the base Transformer and its hidden states.

Task-specific model
model = AutoModelForSequenceClassification.from_pretrained(...)

Gives you:

Transformer
    +
Classification Head

For example:

Input
 ↓
Transformer
 ↓
Hidden states
 ↓
Classification Head
 ↓
2 logits

because our example has:

NEGATIVE
POSITIVE


Logits ⭐⭐⭐⭐⭐

The model doesn't initially output:

POSITIVE = 99%

It outputs logits.

Example:

[-1.56, 1.61]

These are raw, unnormalized scores.

Then:

Logits
  ↓
Softmax
  ↓
Probabilities

For example:

[-1.56, 1.61]
      ↓
[0.04, 0.96]

So:

NEGATIVE → 4%
POSITIVE → 96%

The HF page explicitly emphasizes that logits are not probabilities.


Postprocessing

Finally, the pipeline converts those raw outputs into something useful:

Logits
 ↓
Softmax
 ↓
Probabilities
 ↓
Labels

Example:

[
    {
        "label": "POSITIVE",
        "score": 0.9598
    }
]
